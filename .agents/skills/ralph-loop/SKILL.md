# Ralph Loop — 끝까지 해결

실패가 발생하면 **완전히 해결(Green)될 때까지** 멈추지 않고 디버그 루프를 반복한다.
한 번 실패했다고 에러 메시지만 전달하고 끝내지 않는다.

## 적용 시점

- 지도 마커가 안 보일 때
- Gemini/TourAPI/Supabase API 호출 실패
- Streamlit 페이지 렌더링 에러
- 코스 데이터 추가 후 필터 동작 안 함
- 좌표 불일치로 지도가 엉뚱한 곳을 표시

## 6대 원칙

1. **첫 실패는 시작점** — 에러 로그, 스택 트레이스 철저 분석
2. **환경부터 점검** — `.env`, 패키지 설치, API 키, Supabase 테이블
3. **한 번에 하나의 가설** — 가장 가능성 높고 비용 낮은 것부터
4. **동일 명령으로 재검증** — 수정 후 실패했던 바로 그 조작 반복
5. **객관적 증거** — 터미널 출력, 브라우저 화면으로 성공 확인
6. **포기 기준** — 외부 API 장애, 권한 부족 등 사용자만 해결 가능한 경우만

## 루프 흐름

```
[Streamlit 실행 or 코드 실행 → 실패 감지]
       ↓
[에러 메시지 / 스택 트레이스 수집]
       ↓
[원인 분석 — 1개 가설 수립]
       ↓
[최소 수정 (한 파일, 한 줄이면 한 줄만)]
       ↓
[동일 조작으로 재실행] ─── (실패) ──→ [다음 가설로 루프]
       ↓ (성공)
[완료 보고]
```

## K-Plogging Trail 자주 발생하는 실패

| 증상 | 1순위 가설 | 확인 방법 |
|------|-----------|-----------|
| 지도 마커 누락 | `highlights_en`에 있지만 `HIGHLIGHT_COORDS`에 키 없음 | Python dict 키 비교 |
| "module not found" | `requirements.txt`에 패키지 누락 | `pip install -r requirements.txt` |
| Gemini API 에러 | `GEMINI_API_KEY` 미설정 또는 만료 | `echo $GEMINI_API_KEY` |
| TourAPI 빈 결과 | API 키 만료 또는 좌표 범위 밖 | 직접 URL 호출 테스트 |
| Supabase 크래시 | `SUPABASE_URL`/`SUPABASE_KEY` None | `.env` 파일 확인 |
| 필터 후 코스 0개 | `theme` 값이 `THEMES` 키와 불일치 | 데이터 대조 |

## 완료 보고

```
## 🏁 해결 완료

**실행 명령:** [검증 명령]
**결과:** PASSED — 반복 N회
**수정 사항:** [파일:라인 — 무엇을 왜]
**검증 증거:** [터미널 출력 요약]
```

## 금지 사항

- ❌ 첫 실패 후 "에러가 발생했습니다"만 남기고 중단
- ❌ "직접 이 명령어를 실행해보세요"로 떠넘기기
- ❌ 근본 원인 모른 채 대규모 수정
- ❌ 재실행 없이 "아마 수정되었을 것입니다"
